## B-1. Exactly what the frozen physical source establishes

The project source report [BCRD-INTRINSIC-IDENTITY-CONSERVATION-2026-11-02.md](BCRD-INTRINSIC-IDENTITY-CONSERVATION-2026-11-02.md) fixes upstream physics-lane SHA \`2b50c8112bf5450aa4f30bf6e3a8f83b0ec9ec35\`.

It reports 68 hash-checked files, including 34 Python files and **zero Lean source files**, spread across heterogeneous M1–M7 physical architectures. The report says no unified source-native M1–M7 \`AdmissibleStep\` or universal subject/history map was found. Its historical replay reports 32 of 33 relevant Python controls passed, with one retained numerical-eigenvalue-sort failure adjudicated as an ordering artefact; this reviewer did **not** rerun those 33 controls independently.

\`FrozenBCRDEvents.lean\` and \`BCRDIdentityCharge.lean\` exactly model the M3d \`W_UPDATE\` witness on six basis positions, and the source-conformance script checks original operators against 36 real and 36 imaginary matrix units. The exact permutation is \`(0,1,3,2,4,5)\`; the update swaps two positions, so on that frozen sector it is an involution.

**Reliable conclusion:** an exact, reproducible reversible M3d source transition; a specific cross-architecture candidate parity charge changes by +1 to −1 under it.

**Not entailed:** reversible operation of the whole M1–M7 universe; all physical interactions being the same involution; no actual subject losing consciousness; unbounded continuity or full-X3 agency; every physical event covered by that selected generator.

The original physical report explicitly forbids inferring X3.1 subject continuation or a universal conservation law from this six-state operator. PRs #274–#276 should preserve that original physical scope.
